## Delivery process / root causes of perceived slowness

- Large mixed world/map updates entangle rendering, content geography, authority, schema, browser tests and visual quality. A single PR may be technically broad even when its user-facing theme sounds small.
- Repeated **exact-head** CI is necessary after gameplay changes, but repeated unrelated edits before the prior failed run's evidence is diagnosed waste long browser runs. Diagnose the first causal failure, add a regression that fails before the fix, run targeted coverage first, and only then perform full acceptance on a stabilized candidate.
- Chat-length handoffs, duplicated historical status prose and outdated `README.md`/`TASKS.md` entries cause confusion. Prefer a small living status pointer plus immutable issues, exact commit evidence and one canonical active ticket.
- [Concurrent-agent policy](CONCURRENT_AGENT_WORKFLOW.md) already exists, and [project governance](PROJECT_GOVERNANCE_AND_COMPLEXITY.md#4-one-active-implementation-ticket-means-one) **limits substantial overlapping implementation**. Independent reviewing, art/source evidence, test analysis and isolated proofs may run alongside one active coding ticket. A broader 4-agent cross-domain coding model should not be silently adopted without changing the approved governance and proving conflict isolation.
- More tests, files, merged PRs or AI agents do not prove completion or enjoyable gameplay. Prefer acceptance at an actual player workflow and whole-release boundary.
