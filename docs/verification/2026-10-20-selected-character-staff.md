## Behavior and integration contract

Delegated authority belongs to one explicitly selected verified owned character, with live revocation and strict expiry on each protected operation. The protected single Owner remains an account identity and is never delegated; using protected operations still requires a current playable owned selection. Canonical roles remain `game-owner`, `moderator`, `content-staff`, `event-staff`.

The server derives identity through verified claims/current game-session lease, rejects substituted actor UUIDs, and resolves the current selected character through the existing owned playable roster lookup. `selectedStaffRpcParameters` overrides submitted acting-character IDs; `callSelectedStaffRpc` and all production authoring/operation factories use it. Do not cache capabilities across requests or let a Players editor alter identity/role state.

The additive migration `20261020231118_selected_character_staff_authority.sql` adds character/expiry to role and capability grants, retains unbound predecessor rows as fail-closed history, and adds a selected-character leading argument to installed protected RPC definitions and their protected caller closure. It preserves actual amended definitions, nested Essence/version-floor publication, catalogue CAS and Event audit wrappers. Superseded/account-only public RPC execution is revoked, without reopening superseded writer ACLs. Ordinary current/pinned catalogue/rule readers and gameplay/worker contracts remain unchanged.

Staff lookup resolves an exact character name or verified email to verified identities and all linked characters. Assignment atomically replaces only the chosen character's scope and positive elapsed UTC-day duration (or No Expiry), with explicit legacy binding and version CAS. Existing assignment edits/binding and revocations cannot bypass CAS by sending null. A new, previously unassigned character may use null as the absence precondition. Legacy revocation changes only unbound rows.

The current source has no separate Master Discipline metadata/relationship authoring RPC: its current protected complete-content path covers Skill/Essence/Resonance definitions and source/pair relationships. Player Discipline selection/mastery/catalogue RPCs are preserved. The lost private checkpoint was not recovered or reconstructed by assertion.

Protected RPC argument order is acting selected character UUID, actor UUID, then prior arguments. New Staff contracts are `resolve_master_panel_accounts_v2`, `set_master_panel_character_access_v2`, `revoke_master_panel_character_access_v2`, and `revoke_master_panel_legacy_access_v2`. Read access/operator/directory retain names with selected-character overloads. World history now takes actor character/user plus limit. Site Music writes use `save_site_music_configuration_v2`, with live Owner authority and revision CAS; direct service table writes are revoked.

Owner bootstrap still resolves the exact account to its UUID and inserts the single `game-owner` row with null character/expiry. Its upsert uses `ON CONFLICT(user_id,role) WHERE character_id IS NULL`. Local browser fixtures were updated: Event fixtures now create/select a real character and bind both roles and capabilities to it; Owner bootstrap remains unbound.

The compact Staff directory shows character, authorized email, role, server status, UTC expiry, Edit/Revoke. The focused editor offers existing role presets, explicit target/binding, readable scope, collapsed special permissions and expiry choices. Existing grants require an explicit expiry choice to avoid accidental permanent renewal. Routine written reasons and fake tabs are removed; actor/user/character/time, predecessor role/capability state and the applied scope or disabled state are automatically audited with null notes. Existing modal focus containment/return is reused.
