## Root cause and change

- Existing journal generation concealed commands only when Covert was already present at command start. A successful cast establishing Covert exposed its own Skill identity, cost and positive receipt. New action journals also recognize actual self-applied or queued Covert. Failed/absent applications are not inferred from authored text.
- Initial cast privacy was absent from its delayed native packets. A shared helper pins the same team restriction on receipts and newly queued effects/Summons/Ground areas at native and canonical command boundaries. Existing source restrictions and earlier queued instances are retained. Later activation/entry receipts keep the originating cast’s restriction.
- Pending lifecycle receipts were absent from target privacy classification. The journal now classifies pending and persistent lifecycle facts using their actual status/tag identity. Positive or unknown effects on a Covert recipient remain private; public harm and existing Sensory rules retain their existing policy.
- Pending Covert’s identity was itself visible on the opposing rail. Read projection now omits it. Queued benefits from a protected cast are filtered using the recorded source visibility before rail conversion, including before that cast’s Covert activates. The recipient still sees their own queued benefit; the source Skill identity is not exported. Pending Covert does not conceal unrelated pre-existing public benefits.

These changes add privacy metadata/projection only. Authoritative HP/MP, damage, board state, targeting, timing, costs and native outcomes remain real. The Ground regression records the same 23 damage (1000 → 977); the shared live projection omits a concealed Barrier pool rather than falsifying HP. The separate Barrier/HP-bar implementation must continue to consume viewer-projected pools.

## Historical and live boundary

## Remove/reapply identity and shared-clock rereview

The earlier array-length rule could misclassify a new application at index 0 after the old effect had been removed. Application privacy now uses actual preserved application object membership. A legacy status promoted into its first application array is recognized only when its exact prior application facts survive and the command contains no matching removal/expiry receipt. Canonical remove/reapply regressions cover both a legacy prior row and an already-recorded application array.

The native status still has one shared lifetime. When a newly concealed application changes that row's owner-start/end counts, round count, scope, activation/active phase or skip-current-turn flag, commit records a private shared-lifetime flag on the newly concealed application. The flag stays with its actual source even when other casters also contribute to the merged row, is validated alongside the existing source grant, is cleared from new copied applications and is stripped recursively from public DTOs. Projection then omits that ambiguous merged status while Covert is pending instead of reporting a secret refreshed lifetime beside an old public magnitude. Unchanged clocks still permit the proven earlier public magnitude; unrelated public statuses and independent Barrier pools remain visible. No countdown or expiry mechanic is changed.

Actual canonical REDs were observed for remove/reapply, owner-clock extension and round/scope refresh.
