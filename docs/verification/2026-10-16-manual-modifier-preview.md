# Manual modifier preview — verified development checkpoint

Master Skill, inner Essence Skill and Resonance authoring can now preview a Manual modifier as part of a real reference action. Previously the selector and service only accepted Manual action groups, leaving modifiers without a meaningful battle context. The author chooses a reference Skill identity and, where required, its exact Manual group. The existing authenticated service resolves its current published version, then prepares the complete native command.

The default reference is Basic Attack. The dropdown offers built-in Skill identities, resolved current on the server; an optional group field supports a current published definition with several Manual actions. Unknown, disabled, malformed and ambiguous references reject explicitly. A separate source is required; a modifier never becomes an independent cast. Skill/Essence capture retains its real source, Resonance capture retains its exact sorted pair, and native historical Skill roots use the existing native adapter rather than a fabricated Ability. Canonical roots use the existing shared preparation path.

Costs and projections describe the whole root-plus-modifier command. The root's classification, attack family and intrinsic Discipline determine qualification. Native unmet Requirements or root incompatibility produce an informative illegal preview with no invented costs or outcomes. The fixed fixture does not supply arbitrary statuses or resources to force success. Actual amplified damage, aggregate AP/MP, current reference version/group, Basic binding, input immutability and no-RNG behavior are covered.

All three editors clear preview and publication confirmation when the reference or selected group changes. Revision guards discard late responses. Enabled Skill/Essence modifiers still require a completed current preview; fixture illegality remains informative. Pure-modifier Resonances retain their prior validation/diff publication workflow with optional preview. Disabled modifier Skill and inner-Essence revisions can publish valid edits while retaining their disabled state, without any enabled simulation. Normal action publication defaults and the existing server CAS remain unchanged.
