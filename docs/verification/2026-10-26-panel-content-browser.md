## Independent review I2/I4 recovery repairs

Focused real-workspace handler regressions first failed, then passed:

- I2: create succeeds but its follow-up commit fails. The returned saved draft is now adopted immediately with its stable server identity/revision before committing. Inline edits remain bound to that record (including queued new-definition edits and Essence nested identity rebinding). Retry sends commit for the existing record, never another create or duplicate parent link. The 503 recovery message is conservative: “Created item saved; commit not confirmed. Refresh saved state before retrying.” It does not claim rollback when the server may have committed before readback failed.
- I4: saved B → submit A → revert to B while pending. A latest-editor ref preserves B independently of its dirty-map entry, then compares B against returned A. B remains visible/unsaved and the next commit uses the returned revision.
