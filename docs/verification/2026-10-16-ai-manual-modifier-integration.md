# AI explicit Manual modifier integration

Status: bounded integration passes focused checks, one fresh combined review and the final repository gate. Task15/16 and release remain open. Base `dda3d5f8caa9978d576d73ac283df8a1ca85d2f3`. No roster definition, publication, hosted data or deployment change.

The saved preflight identified a real missing path: AI could quote and select canonical Manual actions but did not choose or forward explicit Manual modifiers. The existing approved command design already permits an AI to choose a Manual bundle on its legal turn. This implementation carries identities through the existing planner → internal intent → shared executor → authoritative Recruit service → repository CAS path. It introduces no separate effect executor, cost formula or player control.

## Resulting behavior

- Consider omission, then stable single attachments and breadth-first combinations of owned, active, owner-eligible captured Manual modifiers. At most the existing difficulty profile's `maxCandidates` bundles are considered per root/target/path, with the existing15attachment command bound retained. Profiles use48/72/96; custom profile validation already caps256. Each candidate receives a real shared atomic quote; incompatible, target-ineligible, unaffordable, cooldown/limit-blocked or malformed candidates are not admitted. Explicit selected execution never silently drops an attachment.
- The four Manual modifier records selected anywhere in the current final design fit inside the minimum existing profile budget, so their possible subsets fit. Larger custom catalogues use deterministic bounded search; this is a heuristic, not a claim to find the globally optimal subset of arbitrary content. Plural target aggregation runs separately for each bundle, preventing variants of one target from becoming duplicate plural selections.
- Reuse the existing projected effect utility. Equal utility prefers fewer attachments before the existing stable key, avoiding optional payment for no additional outcome. Unattached existing stable keys and absent intent fields are preserved. Native Skills and historical native Basic Attack use the same adapters and explicit references; native Basic alternatives are added only for a genuine projected improvement and only when a canonical captured Basic is absent.
- A free Controlled prime carries the chosen exact references without payment or effects. After JSON restore, release candidates use only that captured set; they do not attach a newly available modifier or omit an unaffordable captured modifier. Current target/route and legality are still re-evaluated. The existing shared prime/cancel/release authority owns limits, costs, usage and source maintenance.
- Internal action/prime intents carry optional references. The actual Recruit service forwards them into the same shared command and its existing fingerprint/CAS path. Cancellation remains free. Summon execution receives no new attachment authority. Public decision events and response summaries retain their existing safe shape; private captured references and participant provenance are not returned.

## Scope decisions and remaining acceptance

Ruling: implement this existing Task15/Manual-command design through the present planner and authority, without another product design approval. Optional search and propagation are technical application of the approved reference grammar, not a new combat mechanic; cost if wrong is incorrect choice/payment, guarded by real canonical/native/Controlled/CAS cases.

Ruling: use the existing profile budget for deterministic breadth-first optional bundle enumeration, not an unbounded power set or an AI-only effect simulator. Current final-design subsets fit; custom large-catalogue optimality is explicitly not promised. Cost if wrong is missed custom-content combinations or planning cost; the frontier and actual command bounds are tested.

Ruling: equal projected utility prefers fewer attachments; retain the existing utility model and unattached stable keys instead of adding a new AP/MP/HP valuation formula. Cost if wrong is a suboptimal resource tradeoff, to be assessed in actual legal-build combat balance rather than hidden scoring changes.

Ruling: keep current player controls/readers and catalogue definitions unchanged. Generic authored fixtures cover optional plural/Controlled/native compatibility while the real final Aimed Shot/Focus witnesses stay exact. Cost if wrong is overclaiming whole-roster or human acceptance; those remain open.
