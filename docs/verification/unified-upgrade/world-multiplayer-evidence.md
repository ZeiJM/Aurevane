# World multiplayer and streaming evidence

The [prior authenticated Atlas run](https://github.com/ZeiJM/Aurevane/actions/runs/42372364205) exercised eight disposable sessions in dispersed and hotspot layouts, a sector crossing, a cohort reload, and two simultaneous battle admissions. The zero recorded broadcasts are inconclusive: the sampler parsed every frame as JSON, and normal World polling could satisfy the observed positions. The separate two-player presence-only case observed peer movement in 538 ms. Keep the prior timings as historical evidence for those workloads.

The lockfile pins Supabase JS 2.112.3. Its installed Realtime client reports protocol 2.0.0 and decodes a binary server frame containing JSON user data as a `broadcast` with the `changed` event. The new unit regression reproduces the old sampler returning no observation for that frame. The corrected sampler counts V1/V2 text frames and V2 server broadcast envelopes without saving raw topic strings, identities, JWTs, metadata, or payloads. See the [Realtime wire protocol](https://supabase.com/docs/guides/realtime/protocol#binary-frames).

The revised eight-session case waits for an acknowledged World topic in the current document before starting each movement workload. It checks that the dispersed layouts do not expose the whole cohort and that all eight hotspot snapshots contain the other seven peers, including the player who crossed into the adjacent sector. Full snapshots must contain at most 25 authoritative scene sectors and keep returned peers within them. This does not bound the separate compact public scenery data to 25 sectors.

After the reload burst, all eight must rejoin the exact hotspot topic. Seven idle observers temporarily block general `GET /api/world` reads while an eighth session submits one authenticated walk. For each observer, the gate requires a private `changed` broadcast followed by a browser request to `/api/world/presence` that returns a fresh registration for the observer and the mover's newer authoritative route or arrival. That receipt must keep peer positions and route steps within at most 25 scene sectors and 200 peers, and contain no terrain or atlas payload. The JSON attachment separates current-document joins, binary and text counts, sampled frame bytes, blocked fallback reads, and broadcast-to-receipt evidence. Missing samples remain null in the observer breakdown.

Verification is scoped to test and instrumentation code. The application, database trigger, Realtime policy, terrain, and movement paths are unchanged. Run `Living Atlas browser` on the exact review head and inspect `world-multiplayer-load.json` from `living-atlas-evidence`. The local worktree has no Docker or Podman, so it cannot start the disposable stack. A passing strict gate would substantiate private delivery and scene bounds for this workload only. The larger load ladder, production capacity, and server/asset memory pressure measurements are still open.
