## Actual workflow and authority

The explicit restore-basic-draft operation uses the existing protected handler and operator-authorized service. The server obtains the exact stored historical version or exact builtin Basic version, validates complete identity/kind/envelope, and ignores any client-supplied replacement definition. Missing, malformed, ambiguous, wrong-kind or wrong-identity history fails closed. Disabled historical definitions remain editable drafts. Restore checks the editor-observed current publication base and saves through the existing draft CAS; it does not repoint publication, append a version, alter history, change a loadout choice or affect a captured battle. No new table, migration, SQL function or grant is added.

A publication can race the read before draft saving. This is deliberately a draft-only operation: a competing draft wins CAS without overwrite; a competing publication may make the restored draft's observed base stale, and normal later publication rejects it. Both cases execute against the actual local repository and service. No new atomic catalogue snapshot or physical SQL-lock guarantee is claimed.

Each noncurrent history row offers a version-labelled Restore to Draft button and record-bound confirmation explaining saved-draft replacement. Confirmation and publication are mutually exclusive. Success checks returned Basic identity/version/base/draft counter, updates saved draft CAS and invalidates review. A newer local edit survives an in-flight restore with an explicit unsaved notice; the next Save uses the advanced draft counter. Failure preserves the local draft, history and review. Switching records cancels confirmation. All five records remain independently accessible; only Move, Attack and the selected Support are captured. The public list shows current plus two recent versions while complete internal/server history and publication floors remain intact. Other categories retain their prior Rollback behavior.
