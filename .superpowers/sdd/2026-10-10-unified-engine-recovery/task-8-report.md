## Implementation and interfaces

`createSelectedCharacterRpc` is the production server composition boundary. For each protected RPC it derives verified authentication through `getAuthenticatedActor`, resolves the current selected cookie through `loadSelectedCharacter` / playable ownership, rejects another user’s actor identity, and supplies `p_actor_character_id`. Request JSON cannot supply authority. The selected-character lookup uses the existing request-scoped cache; grants themselves are always queried live, without a cross-request permissions cache.

The additive `20261019003429_selected_character_staff_access.sql` creates a private, RLS-enabled character grant record. Canonical roles remain `game-owner`, `moderator`, `content-staff`, `event-staff`; the existing single Game Owner remains an explicitly documented account-root/bootstrap exception, including no selected character. Owner/delegation/settings/identity powers cannot be granted as special capabilities. Delegated grants require a currently owned character without pending deletion, enabled access and `expires_at > statement_timestamp()`. No Expiry is NULL; positive whole durations use exact 24-hour UTC days (bounded to 1–36500 days). Revocation is immediate at the next protected operation. Assignment checks an optimistic revision and records private actor account/time/action, target character and before/after state with a NULL optional note rather than a fabricated reason.

The migration adds explicit actor overloads by extending the actual current `pg_get_functiondef` bodies. It preserves existing CAS, catalogue snapshot tokens, immutable history, publication floors, locks, audit wrappers and original service-only grants. Legacy signatures cannot authorize a delegated account; the six old account-grant administration/list/discovery RPC ACLs are retired. Existing ambiguous grants stay private and appear as Needs binding until explicit verified character assignment. SQL also rejects self/Owner targets, invented roles/root capabilities and duplicate grants.

Actual protected consumers covered: access/operator readers; Staff handler/page/store; Master page capability checks; combat draft/history/save/publish/set-current (all current kinds, including Resonance `disciplinePair`); Event drafts/history/publication/scheduling/cancellation; live Event list/dashboard/operate/phase/cleanup and scope/emergency checks.
