## Proposed additive implementation

1. Add bounded Owner-only search/read RPCs and strict DTOs: name query and disambiguated character ID, bounded result count and bounded recent actions. SELECT existing facts only, project verified linkage without auth secrets, distinguish supported writable/calculated/protected/future fields. Target fingerprint covers editable character/allocation/build/progression facts rather than changing presence timestamps.
2. Add strict allowlisted gameplay commands and a private append-only support audit. Reject unknown/nested identity, owner, role, capability, expiry, cycle/bootstrap and derived-stat fields. CAS/fingerprint and request-key idempotency apply to actual source state; SQL repeats all critical rules. Supported edits: legal Core allocation; coherent XP/progression correction under current curve; existing legal Primary/Secondary/equipped Skill/support build operations. Show resource values where actually stored; do not create a new persistent resource system solely to expose an editor.
3. Serialize edit admission against real battle creation: take existing account admission lock before character/build locks; reject active or pending participant encounters in SQL after locks. Use bounded NOWAIT/retry on conflicting secondary locks where required, preserving current publication/admission order. No live snapshot overwrites or deferred invisible edits. Preview downstream calculated changes before explicit save.
4. Add private immutable per-battle administrative no-contest receipt/marker, unique on battle session, with actor, selected actor, selected target, exact affected participant set, version, request fingerprint and timestamp. Preserve existing lifecycle enum by using terminal `abandoned` plus explicit `no-contest` outcome marker/event/DTO; this is a dedicated administrative outcome, not ordinary abort. Existing captures/outcomes remain untouched. A global new lifecycle value would unnecessarily change parsers/SQL/readers across historical combat.
5. Recovery preview uses actual participant mapping and battle version. This engine has no safe independent participant removal: whole encounter void is required. Commit requires the exact complete affected character set and preview version/fingerprint. If membership/head changed, return refresh conflict. Never silently void an unconfirmed opponent or teammate.
6. Recovery transaction locks the authoritative session and rechecks pending/active lifecycle, current authority, all participants and claims. Competing normal completion that won is returned as already terminal and is not rewritten; no-contest that won prevents later completion/claims. Match trial's session-first settlement order and use bounded nonblocking account/character/lobby lock admission to avoid inversions with creation/World operations. Real two-session schedules must validate this choice.
7. Insert immutable marker and persist the terminal head/new immutable snapshot/event before cleanup statements. Clean deferred effects/summons/Ground/status/maintenance/primes; cancel linked lobby staging, clocks and spectator links idempotently; active participation is released by terminal head, retaining participant history. Preserve World position/discovery/objectives, training, prior grants and source resource rules; no HP/MP/XP/currency refund. Entire operation rolls back on any cleanup failure.
8. Add a DB-level immutable recovered-head guard: no recovery marker can coexist with active/completed rewrite, even through retained v1, v2 inner, v2/v3 or direct service mutation. Ensure marker/head/receipt cross-checks and append-only marker ACLs cannot be bypassed. Trial claim checks explicit no-contest before receipt/outcome handling. v2 replay/resync should prefer current no-contest head over an older pre-recovery exact replay, preventing stale UI resurrection without changing other exact replay semantics. Terminal analytics distinguishes administrative no-contest.
9. Add compact Owner Players page/client and navigation entry over those services; searchable list and focused profile/editor/recovery confirmation naming every affected character. Reuse shell/character/stat/reference readers. Native browser evidence covers long names, focus, keyboard, mobile and 200% zoom; local fixtures are not hosted/multiplayer acceptance.

New schema must be generated via installed CLI help then `pnpm exec supabase migration new players_no_contest_recovery`; retain all existing migrations. New tables/functions stay private/service-only with explicit ACLs, immutable audits and RLS defense. Source/migration are one reviewed release unit. No hosted mutation during implementation.
